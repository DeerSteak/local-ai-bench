# Local AI Bench 6.1

## Release approval

Ben Funk (DeerSteak), the project maintainer, confirmed on 2026-09-08 that all verification gates were closed and authorized publication of this stable release. This records maintainer approval; it does not claim that the packaging session independently repeated the external verification. Existing exact-runtime platform qualification records retain their own scope and evidence.

## Changes since 6.0

- Prefer compatible official llama.cpp archives and build the same selected release from source when needed. Ubuntu derivatives may use Ubuntu archives; Fedora, RHEL, Arch, Debian, and Rex build locally. Warn when installed ROCm is older than the available matching-architecture Ubuntu archive.
- Maintain the complete llama.cpp toolset within the project, including the separate Vulkan runtime; report newer upstream numeric build identities correctly.
- Configure Rex's standard ComfyUI container with the benchmark model mount, restarting only an idle service when needed.
- Verify resumed model weights immediately before their pending load, show verification progress, and correctly mark recovery after unclean exits.
- Add system/model grouping for llama-batched-bench charts, preserve selected generation lengths, and use an 8K concurrency prompt. Regular llama-bench uses sparse long-context sweeps.
- Apply GGUF chat templates and context headroom consistently, preserve setup selections, and update dependencies.
- Refresh telemetry summaries during recovery, avoid misleading headroom for external ComfyUI processes, and reduce image completion polling to 100 ms.

## Compatibility and migration

Application version: 6.1. Result/run metadata schema: 5. Run-plan schema: 7. Event journal, result bundle, and workload-pack schemas: 1. No schema bump is introduced by release packaging. The existing engine adapter contract, question-bank versions, and neutral-v2 methodology remain separately versioned; runtime build and workload settings must still be matched for performance comparisons. Older result files remain readable.

Existing system/Homebrew llama.cpp installations are left untouched; Setup installs or repairs the project-owned toolset. Source fallback requires the platform compiler and backend toolchain and does not upgrade ROCm. Resume still rejects changed pending model artifacts. Image timings remain client-observed and include up to approximately one polling interval plus request overhead. External ComfyUI memory headroom may be unknown. No new platform-wide qualification or security-audit claim is implied by this release.

## Signed payload and rollback

The release payload contains a source archive, dependency SBOM, third-party notices, source provenance, public signing key, SHA256SUMS, and its detached SSH signature. The provenance names the exact source commit packaged before public payload files were added to the archive branch. The signed v6.1 tag identifies the main release merge, including those public payload files. Private signing material is never included.

Verify the public key fingerprint through a trusted channel, then verify SHA256SUMS with ssh-keygen before checking the listed file hashes. The published verification instructions contain the exact commands. Keep results and model storage when rolling back; use the retained release/6.0 branch or a previously verified signed release. release/6.1 remains as the archived release branch, and release changes are reconciled into develop.
