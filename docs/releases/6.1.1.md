# Local AI Bench 6.1.1

## Changes since 6.1

- Discover complete non-catalog vLLM models in the configured Hugging Face cache and expose them in the GUI and terminal model menus without another download. Preserve registered aliases and reject incomplete indexed snapshots.
- Apply GUI runtime prerequisites to the selected engines and name the selected workloads behind missing-runtime errors. vLLM-only runs no longer incorrectly require llama-server.
- Encode repository IDs consistently in resume artifact keys, including deferred verification, while preserving existing catalog identities and checks for changed or missing weights.
- Show applicable workload energy and efficiency data, add global system combining and persistent multiline system names, improve chart labels, and distinguish tab-specific exported run cards.
- Keep Result History dashboard reuse working after terminal disconnection, limit image charts to applicable resolutions, and guard GUI tests when desktop access is unavailable.
- Update Python and dashboard dependencies and retain the default-branch Vitest dependency grouping configuration.

## Compatibility and validation

Application version: 6.1.1. Result/run metadata schema: 5. Run-plan schema: 7. Event journal and result bundle schemas: 1. Release packaging introduces no schema, engine-adapter, question-bank, workload-pack, or methodology version change. Catalog resume artifact keys remain unchanged; custom repository IDs use escaped logical keys. Model selectors and displayed model names retain their original values. Older results remain readable.

The maintainer reported a successful DGX Spark run using the custom RadixArk Qwen 3.8 Flash Next model and catalog Qwen 3.8 27B after these fixes. That report is functional confirmation, not a new platform-wide qualification record. Automated validation covers Python tests, Pyright, dashboard tests, lint, and TypeScript. No new installer, runtime version, security audit, accessibility review, or platform qualification is claimed by this patch release.

## Release and rollback

The release/6.1.1 branch retains this source release. The signed v6.1.1 tag identifies its merge into main; release metadata is reconciled into develop. This patch does not replace the frozen signed 6.1 payload or publish newly qualified installers. To roll back the source, use the signed v6.1 tag while retaining results and model storage. A run created with custom repository artifact keys requires a version that understands those keys for resume verification.
